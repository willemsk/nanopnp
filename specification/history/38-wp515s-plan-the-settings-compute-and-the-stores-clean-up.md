#### 8.2.38 WP5.15's plan: the settings, compute and the store's clean-up, agreed 10 November 2026

Rulings by the author on 10 November 2026, at `/np-plan wp 5.15`, after WP5.14's merge. The Phase 5 plan's open
decision 10 asked which settings exist beyond the four sections of AJ9, compute and network among them, after a
survey of comparable tools. The session surveyed how COMSOL, ParaView, ChimeraX, VS Code and JupyterLab arrange their
preferences, compute and network included, and put three questions through `AskUserQuestion`. A placement question
followed. A third call put to the author that the chosen clean-up conflicts with AI14, which that round had not
quoted. At the plan's review (CODE_REVIEW_051), two of the review's findings went to the author through
`AskUserQuestion`: the clean-up's guard against a run in another program, and the suite shortcuts. After the review, the author set the
implementing models, and asked whether the GUI reviewer should move to Opus. The letter series continues at AN.

| # | Decision | Consequence | Clause changed, and when |
|---|---|---|---|
| AN1 | **Two compute settings: how many builds and solves run at once, and threads per solve; each run's record states its thread count.** Told that several threads can move a solve's last digits, because its sums run in another order, the author chose this over solves at once alone and over no compute settings. Threads per solve is the one setting that can move a result, and only at rounding | AJ9's rule that nothing that can change a result is a setting holds for every other setting. The thread count joins the run record (FR-25). How it enters a stored result's key is decided at WP5.19's plan. A Compute section joins the four | The design document's *Organisation* and WB-37, in this commit; FR-25's run record, open: WP5.19 |
| AN2 | **No network section in v0.6, and no choice that precludes remote connections or plugins.** The author: "Next to the typical network update, I can imagine that we want to add remote connection capabilities at some point, for example to WSL instances or remote compute servers. Or even plugins (e.g., for custom physics). I think we don't need a network settings yet, but whatever architectural choices we make, it should not preclude these kind of features." | The settings are a registry that a later package or a plugin extends, and a section is data. The server stays on loopback (ADR-004) and speaks to the browser through a network API, so a remote server can be added later | The design document's *Organisation* and WB-37, in this commit |
| AN3 | **The v0.6 list: the four sections hold today's six settings plus reduced motion, a guard that asks before a reset, Reset layout or Quit, recent projects, opening the last project at start, significant figures and the number style; the store gains a size cap and its clean-up.** The author chose the larger list over the proposed one and over a smaller one. Only significant figures, the number style and the store's cap may also be set per project | Each setting lands with the package that first obeys it. The number settings change only how a number is shown; the stored value and the run record keep full precision | The design document's *Organisation*, in this commit; open: WP5.15 |
| AN4 | **The store's clean-up is built in WP5.15, and the compute settings in WP5.19 with the runs it starts.** The author chose this over all three in WP5.15 and over all three in WP5.19 | WP5.15 grows by about two sessions and WP5.19 by about one | The Phase 5 plan, in this commit |
| AN5 | **The store has two clean-up actions: one removes the least recently used results that no run record and no sweep names, and one removes every result.** Asked whether AI14 (a current result is never removed) or the new clean-up holds, the author answered: "How about two buttons, one for each option? ;)". After the second action, a run whose solution is gone rebuilds it when it is next viewed. An entry disappears whole, and nothing is removed while a build or run is running | AI14 is amended: a current result is removed on request. The size cap removes only what no run uses, so it never takes away a result the user can see (decided by WP5.15's plan). The Analysis suite rebuilds a run's missing solution on request | §5.3.2's NOTE on older entries, open: WP5.15; the Analysis suite's rebuild, open: WP5.20 |
| AN6 | *Added 10 November 2026, at WP5.15's plan's review.* **Every walk holds a lock on the store that any program sees, and a clean-up that finds one held removes nothing.** The review found that the plan checked only the workbench's own queue, so a run started from the command line on the same project could lose a result it was about to read. Asked, the author chose a lock across programs over the same lock in WP5.19. A run that starts during a clean-up waits for it | AN5's rule that nothing is removed while a build or run is running holds for every program on the store. The operating system's file locks, with no new library; about half a session more in WP5.15. WP5.19's parallel solves take the same lock | open: WP5.15 (§5.3.2's NOTE) |
| AN7 | *Added 10 November 2026, at WP5.15's plan's review.* **The suite shortcuts follow the bar: Alt+Shift+1 to 5 open Molecular, Continuum, Physics, Study and Analysis.** Physics' place moves Study from 3 to 4 and Analysis from 4 to 5 for an existing user. Asked, the author chose this over keeping 1 to 4 and giving Physics 5 | A user's own binding is kept (AI12), and the changelog names the move | open: WP5.15 |
| AN8 | *Added 10 November 2026, at WP5.15's plan's review.* **The implementing session runs on Opus at high effort, a scoped item on Sonnet at high effort, and Haiku takes only mechanical, repetitive work that is fully specified and needs under 100,000 tokens of context.** The author, after the plan's review: "I think we can upgrade the models.
