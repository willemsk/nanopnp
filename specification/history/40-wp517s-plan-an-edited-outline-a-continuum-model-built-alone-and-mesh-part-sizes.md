#### 8.2.40 WP5.17's plan: an edited outline run with its structure's charge, a continuum model built alone and each mesh part's size, agreed 12 November 2026

Rulings by the author on 12 November 2026, at `/np-plan wp 5.17`, after WP5.16's merge. Three questions went through
`AskUserQuestion`: what a study can run with a contour edited in the Contour tool, since a case that supplies
`inputs.profile` beside `structure:` is refused today (REV-39; FR-33); what a Continuum tool's *Build* runs against,
since only a molecular model is built alone (§5.3.1's NOTE on model files); and whether the Mesh tool's per-part sizes
of the mockup can be typed, since the case holds only the global, wall and scale. The author chose against the
recommendation on all three. A fourth question followed from the third: whether a typed size follows the size scale.
The letter series continues at AP.

| # | Decision | Consequence | Clause changed, and when |
|---|---|---|---|
| AP1 | **A supplied outline beside a structure runs with the structure's charge.** A case may carry `structure:` beside `inputs.profile` where stage 7 deposits a charge from that structure's protonation: stage 1 and the protonation run for the charge, stages 2 to 4 do not, and stage 5 reads the supplied outline in stage 1's frame. Without a deposited charge the structure is read by nothing and stays refused, naming both keys. The author chose "Run it with the structure's charge" (*against the recommendation*), over the reach of today's derived case, a model paired only with a molecular model that has no structure, and over that reach with a PQR file opened in Prepare | The Contour tool's saved edit is a continuum model holding the outline, and a study pairing it with the 2WCD molecular model runs charged. The manifest records the structure, the protonation and the outline, and no stage 2 to 4 artefact. The deposit's solid-share gate refuses an outline drawn in another frame. REV-241's PQR point is not taken by WP5.17; it goes with REV-242's new-model action | §5.3.1's NOTEs on `inputs:` and `inputs.profile`, VER-55's restated NOTE and FR-33's matrix row, in WP5.17 |
| AP2 | **A continuum model is built alone, over a molecular model chosen in its pane.** Each Continuum tool's *Build* walks the continuum model over the chosen molecular model's values, 0.15 M NaCl at zero bias and the solid permittivities of that salt's parameter set, as a molecular model is built alone. The choice is held in the project file; by default it is the molecular model of the first study that names the continuum model, else the project's first. The author chose "Alone, with a chosen molecule" (*against the recommendation*), over building through a study that names the model | A model no study names can be built. A mesh whose wall is `auto` is sized at 0.15 M, so a study at another salt builds its own mesh, while an explicit wall size or `wall_for_concentration_M` is reused by every study. A continuum model that supplies its outline or declares an idealised pore reads no molecular model. The store's clean-up keeps what the build stored | §5.3.1's NOTE on model files, in WP5.17; the design document's Continuum rows, in this commit |
| AP3 | **Every part of a generated mesh can be typed.** `numerics.mesh.maxh_nm` becomes the global size of any generated mesh, not only of an idealised pore, and `numerics.mesh.sizes` takes the four other rows of §5.2.2's table: the pore domain (`protein_nm`), the reservoir domain (`electrolyte_nm`), the reservoir's outer boundary (`arc_nm`) and the axis inside the pore (`axis_in_pore_nm`), each optional; an untyped part takes the table's value. The author chose "Type every part" (*against the recommendation*), over typing the global and wall sizes and showing the rest | A case that types none keys and meshes as today (VER-62). A typed part moves stage 6's key and no other. Beside `geometry.pore`, whose mesh reads only the global and wall sizes, a typed part is refused naming it | §5.2.2's NOTE beside the size table and §5.3.1's NOTE on `numerics.mesh`, in WP5.17; the design document's Mesh row, in this commit |
| AP4 | **A typed size is a base that the size scale multiplies**, as the wall size and an idealised pore's global size already are. The author chose this (*the recommendation*), over a typed size that ignores the scale as the mockup's table read | The scale stays one knob over every size, a coarse trial keeps the proportions typed, and no existing key moves | As AP3 |
