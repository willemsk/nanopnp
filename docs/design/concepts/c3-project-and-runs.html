C3 Project and runsStrengths and weaknesses As in an IDE: a browser of the project folder, each item opened as a document.

Principle. The project folder (S11) is the workbench. Structures, cases, runs, comparisons and sweeps are files; each opens as a document whose tabs are the areas that apply to it. Runs queue at the bottom.

PersonaStrengthsWeaknesses
P1 Method developersMany cases, runs and sweeps side by side; the folder is what the command line and scripts see.The live link from a run back to its case is a jump between documents.
P2 Computational scientistsLibraries of models and results (S11) are first class; a variant is a diff of its parent; the queue is the author's batch mode.More windows to manage; the pipeline order lives inside each document.
P3 ExperimentalistsTheir files are where they expect them.An empty project and four kinds of item is a hard start; "new case from this structure" must carry them.

Job 1 crosses three documents: structure, case, run. Job 2 is natural: derive, queue, compare, all kept in the project. Live links (S6) hold within a document; across documents they become navigation.
